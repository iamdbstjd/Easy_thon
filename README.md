## 왜 만들었나

- 전세사기 피해자로 인정된 사람의 약 75%가 20·30대다 (2025년 5월 말 기준, [국토교통부 국회 보고](https://www.kukinews.com/article/view/kuk202506260209)).
- 집의 위험 정보(등기부, 건축물대장, 실거래가)는 이미 공개되어 있다. 문제는 처음 집을 구하는 사람이 그 서류를 읽고 해석하지 못한다는 것이다.
- 대학가 원룸은 대부분 보증금 있는 월세다. 근저당이나 선순위 보증금 때문에 보증금을 못 돌려받는 구조는 전세와 같다.

## 다른 서비스와 무엇이 다른가

> 다른 서비스는 **집**을 진단한다. 이 프로젝트는 사인하기 직전의 **계약서**를 진단한다.

부동산 앱과 공공 앱의 위험진단은 대부분 주소를 넣고 공공 데이터로 그 집을 평가한다. 이 방식으로는 사용자 손에 있는 계약서를 볼 수 없다. 이 프로젝트는 등기부와 계약서를 서로 대조한다.

| | 주소 기반 위험진단 | 집키미 |
|---|---|---|
| 넣는 것 | 주소 | 등기부 + 사인할 계약서 |
| 진단 대상 | 집 | 집 + 계약서 (둘을 대조) |
| 계약서 임대인이 진짜 소유자인가 | 알 수 없음 | 확인 |
| 계약서 동·호수가 등기와 같은가 | 알 수 없음 | 확인 |
| 보호 특약이 계약서에 있는가 | 알 수 없음 | 확인 |
| 결과 | 위험 등급 | 위험 신호 + 원문 근거 + 계약서 수정 요청서 |
| 계약서를 고쳐 받으면 | 알 수 없음 | 요청한 수정이 실제로 들어갔는지, 고친 뒤에도 남는 위험이 무엇인지 비교 |
| 계약 후 등기가 바뀌면 | 바뀌었다는 알림 (일부 앱) | 그 변화가 내 계약서 특약을 어겼는지, 잔금을 보내도 되는지 판단 |
| 쓰는 때 | 집을 고를 때 | 사인하기 직전부터 잔금·입주 다음 날까지 |

두 방식은 경쟁보다 보완 관계다. 공공 위험진단 결과도 나중에 검토서에 함께 넣을 수 있다.

## 주요 기능

- **계약서·등기부 대조표**: 임대인, 소재지·호수, 보증금, 계약일, 특약을 계약서 값과 등기부 값으로 나란히 놓고 일치 여부를 보여 준다.
- **계약서 수정 요청서**: 고칠 곳, 넣을 특약, 계약 전에 받을 서류를 한 장으로 만든다. 복사하거나 A4로 인쇄해 공인중개사·임대인에게 보여 줄 수 있다.
- **수정 전·후 비교**: 요청서를 보여 주고 고친 계약서를 받으면, 고친 계약서 하나만 올려 처음 계약서와 비교한다. 요청한 고칠 곳·특약이 몇 건 반영됐는지, 위험 신호가 어떻게 바뀌었는지, 계약서에서 무엇이 달라졌는지를 보여 준다. 요청을 모두 반영해도 신탁·시세처럼 계약서로 고칠 수 없는 위험은 남는다는 것을 첫 화면에 함께 적는다. 등기부와 직접 입력한 값은 방금 검사에 쓴 것을 그대로 쓰고, 아무것도 저장하지 않는다.
- **계약 후 재확인 (잔금 전·입주 후)**: 계약서와 오늘 뗀 등기부를 올리면 계약일 이후 새로 생긴 근저당·압류·소유권 이전을 찾고, 계약서 특약(담보 설정 금지, 근저당 말소)을 어겼는지 판정한다. 대항력은 전입신고 다음 날 0시에 생기므로, 잔금일·전입일에 끼어드는 권리를 잡아내는 것이 목적이다. 아무것도 저장하지 않는다.
- **서류 읽기**: 등기부등본과 계약서(PDF나 사진)를 AI(OpenAI GPT 또는 Claude)가 정해진 JSON 형식으로 옮긴다. 한 서류를 여러 파일로 올려도 된다 (쪽마다 찍은 사진, 나눠 저장한 PDF). 올린 순서대로 한 서류로 이어서 읽는다.
- **보내기 전에 가리기**: 계약서 사진은 AI에 보내기 전에 주민등록번호·전화번호·서명·계좌번호 같은 곳을 손가락이나 마우스로 칠해 가릴 수 있다. 가린 사진만 전송된다.
- **전송 고지와 동의**: 서류를 올리는 화면마다 어디로(OpenAI, 미국) 보내고 얼마나 남는지 알리고, 동의해야 분석을 시작한다. 앱 안에 개인정보 처리 안내 화면이 있다.
- **실거래로 본 시세와 보증금**: 등기부 주소로 국토교통부 실거래가(최근 12개월)를 찾아, 같은 건물(번지) → 같은 동 비슷한 면적 순서로 고른 매매 중간값을 시세로 채운다(R5가 쓴다. 사용자가 고칠 수 있다). 주변 전세·월세 보증금 중간값과 이 집 보증금의 차이, 찾은 거래 목록을 대조표 아래에 보여 준다. 단독·다가구는 번지가 일부만 공개되고 매매가가 건물 전체 값이라 시세는 채우지 않고 같은 동 보증금만 보여 준다.
- **건축물대장으로 본 용도**: 등기부 소재지번으로 국토교통부 건축물대장(건축HUB)을 찾아 건물 주용도와 내 호실의 전유부 용도를 채운다(R10이 쓴다). 사용승인일·세대·가구 수도 보여 준다. 공개 자료에는 위반건축물 표시가 없어 R9는 "확인 못 함"과 확인 방법을 안내한다.
- **위험 신호 13가지 검사**: 규칙 엔진이 소유자·신탁·압류·근저당·시세 비율 등을 확인하고, 신호마다 원문 근거와 할 일을 보여 준다.
- **종합 판정**: 계약 보류 권장 / 추가 확인 필요 / 확인 미완료 / 큰 위험 신호 없음.
- **다음 행동**: 계약 일정(잔금일·입주일 캘린더 파일)과 계약 전·잔금일·입주일 체크리스트.
- **틀린 값 고치기**: AI가 읽은 값을 사용자가 확인하고 고친 뒤 다시 검사할 수 있다.
- **예시 데이터**: API 키나 인터넷 없이도 예시 A·B·C, 계약 후 재확인 예시, 수정 전·후 비교 예시로 전체 흐름을 볼 수 있다.

## 동작 방식

```
등기부     ─┐
            ├─> FastAPI ─> AI (GPT 또는 Claude): 서류를 JSON으로 옮기기 (판단하지 않음)
계약서     ─┘                  │
                               v
                  사용자가 읽은 값 확인·수정
                               │
                               v
                  규칙 엔진 R1–R13 ─> 검토서 (판정 + 근거 + 할 일)
```

설계 원칙:

1. **AI는 읽기만 한다.** 위험 여부는 판단하지 않는다.
2. **판단은 규칙 코드가 한다.** 같은 입력이면 항상 같은 결과가 나온다.
3. **모든 결과에 근거를 붙인다.** 사용자가 원문과 대조할 수 있다.
4. **모르면 모른다고 한다.** 읽지 못한 항목은 "해당 없음"이 아니라 "확인 못 함"으로 표시한다.
5. **단정하지 않는다.** "사기", "안전" 같은 판정을 내리지 않는다.

## 위험 신호

| ID | 신호 | 판정 |
|---|---|---|
| R1 | 임대인·소유자 불일치 | 계약서 임대인이 등기부 현재 소유자가 아니면 위험, 공동소유면 주의 |
| R2 | 신탁등기 | 소유권이 신탁회사에 있으면 위험 |
| R3 | 압류·경매 등 제한 | 압류·가압류·가처분·가등기·경매 기록이 있으면 위험 |
| R4 | 임차권등기 | 임차권등기명령 기록이 있으면 위험, 그 밖의 등기된 임차권은 주의 |
| R5 | 시세 대비 보증금 비율 | (선순위 채권 + 보증금) ÷ 시세가 80% 이상이면 위험, 70% 이상이면 주의 |
| R6 | 먼저 잡힌 담보·전세권 | 근저당·전세권이 있으면 주의 |
| R7 | 다가구·단독 | 다른 세입자 보증금이 등기에 안 나오는 구조면 주의 |
| R8 | 최근 소유권 변동 | 기준일로부터 90일 안에 소유자가 바뀌었으면 주의 |
| R9 | 위반건축물 | 건축물대장에 위반건축물 표시가 있으면 위험 |
| R10 | 주거용이 아닌 용도 | 근린생활시설 등 주거용이 아닌 용도면 주의 |
| R11 | 주소·호수 불일치 | 호수가 다르면 위험, 주소 확인이 필요하면 주의 |
| R12 | 보호 특약 없음 | 담보 설정 금지·근저당 말소 특약이 없으면 주의 |
| R13 | 오래된 등기부 | 열람한 지 3일 이상이면 주의 |

규칙은 [`backend/app/rules/engine.py`](backend/app/rules/engine.py)에 있다.

## 시작하기

Python 3.13, Node.js 24에서 테스트했다.

### 백엔드

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows: .venv\Scripts\pip install -r requirements.txt
cp .env.example .env                          # 실제 서류를 분석하려면 OPENAI_API_KEY (또는 ANTHROPIC_API_KEY) 입력
.venv/bin/uvicorn app.main:app --reload --port 8000        # 개발
.venv/bin/uvicorn app.main:app --workers 3 --port 8000      # 시연·여러 명이 함께 쓸 때
```

API 문서(Swagger)는 http://localhost:8000/docs 에서 볼 수 있다. 서버는 요청 사이에 아무것도 공유하지 않으므로 `--workers`로 프로세스를 늘려도 된다.

### 프론트엔드

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

### 실행 모드

| 모드 | 방법 | 필요한 것 |
|---|---|---|
| 실제 분석 | 서류 올리기 | 백엔드 + OpenAI 또는 Claude API 키 |
| 예시 | 시작 화면의 예시 결과 링크 (A·B·C, 계약 후 재확인, 수정 전·후 비교) | 백엔드 (API 키·인터넷 없어도 됨) |
| 모의 화면 | http://localhost:5173/?mock=1 | 프론트엔드만 (화면 작업용) |

### 환경변수 (`backend/.env`)

| 이름 | 설명 |
|---|---|
| `OPENAI_API_KEY` | OpenAI API 키. 이 키나 `ANTHROPIC_API_KEY` 중 하나만 있으면 된다. 둘 다 없으면 서류 읽기만 503을 내고 나머지는 동작한다 |
| `OPENAI_MODEL` | OpenAI 모델. 기본 `gpt-5.5` |
| `OPENAI_REASONING_EFFORT` | 추론 강도. 기본 `low` |
| `ANTHROPIC_API_KEY` | Claude API 키 |
| `AI_PROVIDER` | 두 키가 다 있을 때 쓸 쪽 (`openai` 또는 `anthropic`). 없으면 OpenAI |
| `EXTRACT_DEADLINE_SECONDS` | 서류 읽기 전체 제한 시간. 기본 85초 (화면이 90초에 포기하므로 그보다 짧게) |

## 배포

화면과 서버를 컨테이너 하나로 묶는다. 서버가 `/api`와 빌드한 화면(`/`)을 같은 주소에서 내준다 (`SERVE_FRONTEND=1`).

```bash
docker build -t jachwibang .
docker run -p 8000:8000 -e OPENAI_API_KEY=... -e DATA_GO_KR_SERVICE_KEY=... -e JUSO_API_KEY=... jachwibang
```

- **Render**: New → Blueprint → 이 저장소를 고르면 `render.yaml` 설정(무료, Docker)으로 만들어진다. API 키 3개는 그때 Render 화면에 넣는다.
- API 키는 이미지와 저장소에 넣지 않는다 (`.dockerignore`가 `.env`를 뺀다).
- 컨테이너에서는 같은 IP의 서류 읽기를 시간당 60번, 시세 찾기를 200번까지만 받는다 (`RATE_LIMIT=1`, OpenAI 비용·남용 방지). 넘으면 429. 행사장처럼 여러 사람이 한 IP로 나가는 곳을 생각해 넉넉히 두었고, `RATE_LIMIT_EXTRACT_PER_HOUR`·`RATE_LIMIT_MARKET_PER_HOUR`로 바꿀 수 있다.
- 무료 Render는 15분 동안 요청이 없으면 잠들고, 다음 첫 요청에 1분 가까이 걸린다.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | AI 키 설정 여부 |
| POST | `/api/extract` | 등기부(필수)·계약서(선택)의 PDF나 사진을 받아 JSON으로 옮긴다. 서류마다 여러 파일 가능 (같은 필드 이름을 반복) |
| POST | `/api/check` | 읽은 값을 받아 검토서를 만든다. AI를 부르지 않는다 |
| GET | `/api/demo/{A,B,C}` | 예시 입력값 |
| POST | `/api/checklist.ics` | 계약 일정을 캘린더 파일로 만든다 |
| POST | `/api/recheck` | 오늘 뗀 등기부와 계약서로 계약 후 재확인을 한다. AI를 부르지 않는다 |
| GET | `/api/demo/recheck-A` | 계약 후 재확인 예시 입력값 |
| POST | `/api/extract/contract` | 고친 계약서만 받아 JSON으로 옮긴다 (여러 파일 가능) |
| POST | `/api/compare` | 수정 전·후 검사 입력을 받아 비교서를 만든다. AI를 부르지 않는다 |
| POST | `/api/market` | 검사 입력의 등기부 주소로 실거래 시세와 주변 보증금을 찾는다. 실패해도 200과 status로 알린다 |
| POST | `/api/building` | 검사 입력의 등기부 소재지번으로 건축물대장의 주용도·호실 용도를 찾는다. 실패해도 200과 status로 알린다 |
| GET | `/api/demo/compare-C` | 수정 전·후 비교 예시 입력값 |

데이터 형식은 [`backend/app/schemas.py`](backend/app/schemas.py)가 기준이다.

## 개인정보

- 올린 파일은 디스크에 저장하지 않는다. 메모리에서만 처리하고, 크기 제한을 넘으면 읽는 도중에 끊는다. 브라우저 저장소에도 남기지 않는다.
- 서버 로그에는 이름·주소·서류 원문을 남기지 않는다. 입력 오류 응답도 입력값을 되돌려 보내지 않는다.
- 주민등록번호(하이픈 없는 형태, 일부만 가린 형태 포함)와 전화번호는 서버 응답과 화면 양쪽에서 가린다.
- 서류 내용은 분석을 위해 AI API로 전송된다. 기본은 OpenAI(미국)이며, 올리기 전에 이 사실을 알리고 동의를 받는다.
  - OpenAI API로 보낸 데이터는 기본적으로 학습에 쓰이지 않는다. 응답 저장은 끈다(`store: false`). 다만 남용 감시 기록은 OpenAI 쪽에 최대 30일 남을 수 있다 ([OpenAI 안내](https://developers.openai.com/api/docs/guides/your-data)).
  - 계약서 사진은 보내기 전에 사용자가 직접 가릴 수 있다. PDF 계약서는 가릴 수 없으므로 화면에서 사진으로 올리라고 안내한다.
- PDF 검사는 메모리·시간 제한을 둔 별도 프로세스에서 하고, 그 프로세스에는 환경변수(API 키)를 넘기지 않는다.
- 시세를 찾을 때는 등기부 주소 중 '시도 시군구 읍면동'까지만 행정안전부 주소 API로, 시군구 코드와 연월만 국토교통부 실거래가 API로 보낸다. 같은 건물인지는 받은 거래를 서버에서 번지로 맞춰 본다.
- 건축물대장은 지역 코드와 번지로만 찾는다. 호수는 보내지 않고 건물 전체 전유부를 받아 서버에서 내 호실을 고른다. 이름은 어느 공공 API에도 보내지 않는다. 요청 주소에 인증키가 들어가므로 httpx 요청 로그는 끈다.

## 한계

- **법률 자문이 아니다.** 결과는 참고 정보이며 보증금의 안전을 보장하지 않는다.
- 등기부만으로는 선순위 보증금, 집주인의 세금 체납, 보증사고 이력을 알 수 없다. 검토서에 따로 확인하는 방법을 안내한다.
- AI 추출은 가상 예시 서류(A·B·C 등기부, 계약서 PDF·사진, 잔금 전 등기부)로만 확인했다. `gpt-5.5`(low)로 서류 두 장에 6–13초, 종합 판정은 모든 예시에서 예시 입력값과 같았다. 실제 등기부로는 아직 충분히 검증하지 않았다.
- 등기부 PDF와 PDF 계약서는 보내기 전에 가릴 수 없다. 등기부는 누구나 열람할 수 있는 공개 서류이고, 계약서는 사진으로 올리면 가릴 수 있다.
- 서류 읽기는 프로세스마다 업로드 6건, AI 호출 4건까지 동시에 처리하고, 그보다 많으면 기다렸다가 85초 안에 자리가 나지 않으면 "지금 서류를 읽는 사람이 많아요"(BUSY)로 알린다.
- 연결 헤더를 아주 느리게 보내는 공격(slowloris)은 앱보다 앞단에서 막아야 한다. 공개 배포 때는 리버스 프록시를 둔다. macOS에서 시연할 때는 `ulimit -n 4096`으로 파일 수 제한을 올려 둔다.
- 실거래가 API는 연결했다 (`DATA_GO_KR_SERVICE_KEY`, `JUSO_API_KEY`). 키가 없거나 거래가 부족하면 시세를 채우지 않아 R5가 "확인 못 함"으로 나온다. 실거래는 동·호수가 공개되지 않고, 보증금이 작은 월세는 신고 대상이 아니어서 빠질 수 있다. 시세는 매매 중간값이라 참고값이다.
- 건축물대장 공개 API에는 위반건축물 표시가 없어 실제 분석에서 R9는 "확인 못 함"으로 나온다 (정부24·세움터에서 확인하도록 안내). 건축물대장 서버가 가끔 시간 초과를 내서 호출마다 두 번까지 다시 부른다. 예시 데이터에는 값이 들어 있다.
- 업로드 상한: 서류마다 파일 10개·쪽 수 합계 30쪽(사진 한 장은 한 쪽), 파일 하나 10MB, 한 번에 20MB. 사진은 화면에서 긴 변 1,600px JPEG로 줄여 보낸다. 사진으로 찍은 등기부는 가상 예시 서류를 사진으로 바꿔 확인했고, 실제 종이 등기부 사진으로는 아직 충분히 검증하지 않았다.
